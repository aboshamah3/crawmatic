## Deviations

1. **The fleet lease is taken in `scrape_core/limiter.py`+`targets.py`, not a new `middlewares/limiter.py`.** Exactly as CONTEXT.md's B5 note directs (the plan's path is stale; no such module exists, and creating one would fork admission away from the browser spider, which shares `scrape_core.targets`). Impact: NONE — this is the packet's own instruction.

2. **`transport` is a coarse `FleetTransport` (`HTTP` / `BROWSER`), not a full `AccessMethod`.** A host cannot distinguish `DIRECT_HTTP` from `PROXY_HTTP`, so giving them separate fleet ceilings would let the fleet double its own limit by escalating transport — the exact failure the gate exists to prevent. Browser navigations keep their own ceiling, as the plan's "browser navigations and HTTP requests count one lease each" implies. Impact: MINOR (key shape; the acceptance criteria name `transport` without fixing its domain).

3. **Per-domain overrides are read via a primed per-process cache, not a per-request query.** `load_targets` calls `prime_fleet_limits_cache(session, {t.domain ...})` — ONE indexed `SELECT ... IN` inside the transaction it already holds off-reactor — so `acquire_fetch_permission` resolves the ceiling as a pure dict lookup. A per-request `await_in_thread(resolve_fleet_limits, ...)` would have put a DB round trip (and a thread hop) in the reactor-thread scrape path, which `contracts/reactor-seam.md` forbids, and would have hung every existing unit test that drives this coroutine under `asyncio.run` with no Twisted reactor. `resolve_fleet_limits` still supports a lazy `session_factory` for callers outside the spider. Impact: MINOR.

4. **`acquire_permission`'s new `fleet_limits` parameter defaults to `None`, which skips the gate.** Pre-B5 callers and tests are byte-for-byte unaffected (pinned by `test_omitting_fleet_limits_reproduces_the_pre_b5_behaviour`). Impact: NONE.

5. **`costauth/service.py`: the fleet snapshot is opt-in and off by default.** The packet says `_check_concurrency` stays tenant-scoped and reads a fleet snapshot "for denial *reasons* only". `CostAuthorizationService` holds no Redis client, so wiring one unconditionally would have been a real behavioural change to a money gate. Instead: a `fleet_snapshot_reader` constructor kwarg (default `None`) and `_check_concurrency(..., req=req)`; with the default, every denial message is unchanged. Nothing branches on the snapshot; admission remains the Redis lease. Impact: MINOR.

6. **`tests/unit/test_observability_logs.py` was edited** (three stub signatures gained `fleet_limits: Any = None`). Not listed in scope, but unavoidable and mechanical: those stubs replace `acquire_permission`, whose signature grew. Impact: NONE.

7. **Docstrings in `app_shared/limiter/fleet.py` may not name `scrape_core`.** `tests/unit/test_import_boundaries.py` forbids the literal *string* anywhere under `app_shared/`, so two prose references were reworded ("the scraping runtime's reactor-safe limiter seam"). Caught and fixed by the gate. Impact: NONE.

## Notes for reviewer

- **`domain_rules` is a NEW table and stays that way.** The packet made "put the fleet limits on an existing table" a MATERIAL/ESCALATE decision; I did not choose it — I implemented the packet's stated model. It is deliberately distinct from the tenant `DomainAccessRule` (workspace-scoped, tenant-writable) and from `domain_playbooks` (strategy, not capacity). Both distinctions are argued in the model docstring and the manifest entry.
- **C1's `request_timeout_seconds` is a catalog-only `ADD COLUMN`.** Every non-key column is nullable with no server default and `NULL` means "use the setting", so a later column needs no rewrite and no backfill.
- **No `workspace_id`, filed SYSTEM, `SELECT`-only for every runtime role.** `crawmatic_scraper` gets `SELECT` because the spider's cache-priming query runs on that role; `crawmatic_app` deliberately has no `UPDATE` (the A3 fleet-table rule, enforced by `test_app_has_no_update_on_fleet_tables_except_the_evidenced_exception`).
- **Untested path:** the browser spider's release is verified structurally (source-level assertions over `parse`/`errback`) rather than by driving scrapy-playwright, which needs a browser node. An end-to-end browser assertion belongs in `tests/integration`.
- **Fleet-limit cache generation is 60s**, so an operator's `domain_rules` edit takes effect fleet-wide within one generation per process. Priming happens at `load_targets`, i.e. once per spider run — a long-running spider keeps the ceiling it started with for the run's duration unless a generation lapses. That is deliberate (it cannot be tightened without a per-request query) but worth knowing before an operator expects an override to bite mid-run.
- **`ScrapeErrorCode.FLEET_LIMITED` is now emitted** on the deferred target. C1's classification and D5's scorecard must treat it as evidence about *fleet capacity*, never about the domain — nothing was fetched, no socket opened. The enum member's docstring says so explicitly.
- **Interaction with PB-6:** `config.py` was edited by appending a separated block after PB-6's `SCRAPYD_MAX_PENDING_PER_NODE`; the file was re-read immediately before writing. No other shared file overlaps.
