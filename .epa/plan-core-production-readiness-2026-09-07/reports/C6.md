## Notes for reviewer

- **The paid predicate is a conjunction and both halves are load-bearing.**
  `provider <> 'direct'` alone still reads `'browser'` for a direct navigation;
  `proxy_provider_id IS NOT NULL` alone is a logical-row hint with no physical operation
  behind it. `test_a_provider_named_direct_is_never_reported_as_proxied` pins the second
  half specifically.
- **`op_totals` is joined and MAXed, never summed, in the outer aggregate.** It holds at
  most one row per `(workspace, product, cycle)`, so `MAX` is an identity — the same shape
  the pre-existing `bool_or(per_check.observed)` uses. A `SUM` there would re-introduce
  the exact over-count F17 removes; `test_operation_facts_are_maxed_not_resummed_across_matches`
  guards it.
- **The child join uses `OR`** (`network_request_id = ... OR parent_operation_id = ...`).
  Correct, and it is the only way to reach subresources, but it is not a cheap join
  shape. `ix_network_operations_parent_operation_id` exists; if the export ever gets slow
  on a large window, that `OR` is the first thing to look at (a `UNION ALL` of two
  equi-joins is the usual rewrite). It was NOT pre-optimised here — the partitioned scan
  is still bounded and still happens once (`FROM request_attempts` appears exactly once,
  asserted).
- **`network_operation_allocations` is RLS-FORCED and workspace-owned.** The export is a
  deliberate cross-workspace sweep (already so documented), and the allocation join
  carries an explicit `workspace_id = attempt_scan.workspace_id` predicate, so each row's
  money is attributed to the workspace that owes it. `scripts/check_workspace_scoping.py`
  passes. **A tenant-role session running this query will see zero allocations** — it must
  be run on the admin/system connection, exactly as it already is.
- **The denial counter is process-local and monotonic.** It is a Prometheus COUNTER
  rendered per process; a worker restart reads as a reset, which is what a counter is for.
  It is incremented in `CostAuthorizationDenied.__init__` — the one construction site
  every denial passes through, including B5's fleet reasons — so constructing that
  exception in a test increments it. `reset_costauth_denials()` exists for that.
  **Untested path:** aggregation across processes. If the ops endpoint is expected to
  report a fleet-wide denial rate rather than one API process's, that needs a durable
  sink and is a separate task.
- **`estimated_requests` is documented as the COALESCED unique physical count, but nothing
  computes that coalescing yet** — `first_rung_reservation` carries the number it is
  given. The caller (the blocked `tasks_jobs.py` edit) is what must pass the coalesced
  count; `app_shared.jobs.batching` already has coalescing logic
  (`test_jobs_batching_coalescing.py`) for the follow-up to use.
- No Alembic revision was added. One head (`a7c31d0f9e42`, PC-3's) at completion.
- The integration module skips cleanly (7 skipped) when `NETWORK_OPS_TEST_DATABASE_URL`
  is unset, so it costs a CI run without Docker nothing.
