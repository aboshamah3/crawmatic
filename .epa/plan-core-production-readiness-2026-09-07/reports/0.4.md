## What the isolation actually does

`tests/conftest.py`:

1. `isolated_unit_environment` (session-scoped, autouse) rewrites
   `DATABASE_URL` → `postgresql+psycopg://invalid:invalid@127.0.0.1:1/invalid`,
   `REDIS_URL` → `redis://127.0.0.1:1/0`, and `SCRAPYD_HTTP_URLS` /
   `SCRAPYD_BROWSER_URLS` → `http://127.0.0.1:1` via
   `pytest.MonkeyPatch.context()` (the `monkeypatch` fixture is function-scoped
   and cannot be requested from a session-scoped one), then calls
   `app_shared.config.get_settings.cache_clear()` on the way in AND out.
2. `_real_environment_for_integration_tests` (function-scoped, autouse) restores
   the pre-patch values around any test carrying the `integration` marker, so
   the exemption is **per test**, not per session.
3. `pytest_collection_modifyitems` marks everything collected from
   `tests/integration/` as `integration`.

Port 1 is reserved and nothing binds it, so a unit test that reaches out fails
in milliseconds with `ConnectionRefusedError` rather than hanging on a timeout.
"Invalid, not missing" is deliberate: a *missing* variable would fail at
`Settings()` construction and hide the difference between "this test needs
config" and "this test needs a live server".

## The 13 tests that broke, and why the fix is a test change

`tests/unit/test_rate_limiter.py` (4) and `tests/unit/test_stats_buffer.py` (9)
each had a `_redis_client()` helper reading **`REDIS_URL`** as an opt-in signal:
unset → hand-rolled in-memory `_FakeRedis`; set → `redis.Redis.from_url(...)`.
Which client the file exercised was therefore a property of the ambient
environment — exactly the audit §2 defect — and once the fixture always sets
`REDIS_URL` (to a dead port), the opt-in read as "connect to 127.0.0.1:1" and
the whole file failed on `ConnectionError`.

Fix: the opt-in moved to a dedicated `CRAWMATIC_TEST_REDIS_URL`, so the fake is
the deterministic default everywhere and pointing the same assertions at a real
server (`CRAWMATIC_TEST_REDIS_URL=redis://127.0.0.1:6379/15 pytest ...`) is a
deliberate act. No production code was touched, and no test's assertions
changed — only which client the helper hands them. Verified: 31 passed.

There is no local Redis on this box (`127.0.0.1:6379` refuses), so the
opt-in branch could not be exercised end-to-end here; it is two lines
(`os.environ.get` + `Redis.from_url`) unchanged from the code that was
previously reached whenever `REDIS_URL` was set.

## Deviations
- **`tests/conftest.py` was CREATED, not modified.** The packet's CONTEXT.md
  excerpt says "`tests/conftest.py` exists as the root fixture file"; it does
  not — `find . -name conftest.py` (excluding `.venv`) returned nothing at all
  before this task. Same file, same content, no behavioural difference.
- **`pytest_collection_modifyitems` auto-marks `tests/integration/`** — not
  named in the plan. It is load-bearing for the criterion as written: the
  exemption is marker-driven, but only 2 files under `tests/integration/`
  actually carry `@pytest.mark.integration`, and `.github/workflows/ci.yml`
  runs several integration files directly with no `-m` filter
  (`test_rls_cross_workspace.py`, `test_tenant_isolation_roles.py`,
  `test_compose_smoke.py`, ...). Without the auto-marking those CI jobs would
  have been handed the dead-port environment and failed for a reason unrelated
  to the code. The marker's registered description in `pyproject.toml` ("needs
  the docker-compose DB/pgbouncer stack") already describes every test in that
  directory, so this makes an existing convention explicit rather than
  inventing policy. Side effect: `-m "not integration"` now also deselects
  `tests/integration/` tests wherever they are collected — which is the
  documented meaning of the marker.
- **The exemption is per test, not per session.** A session-scoped decision
  ("did we collect any integration test?") would have silently disabled the
  isolation for the whole suite whenever someone ran `pytest tests/unit` without
  `-m "not integration"` — `tests/unit/` itself contains integration-marked
  tests. The fixture that does the monkeypatching is session-scoped exactly as
  the criterion specifies; a second, near-free function-scoped fixture applies
  the exemption.
- **Two extra test files' `_redis_client` helpers were changed** (Step 2 of the
  plan explicitly anticipates this: "fix any test that depended on ambient env
  — each fix is a test change, not production code"). Recorded here because the
  packet's scope line named only `tests/conftest.py`.
- **`tests/unit/test_unit_environment_isolation.py` is new** and not named in
  the packet. A guard nobody tests is a guard that can be deleted by accident.
