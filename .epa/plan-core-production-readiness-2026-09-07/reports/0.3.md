## What was built

**`scripts/config_diff_railway.py`** — reads a NAMES file
(`railway variables --service <s> --kv | cut -d= -f1`) and diffs it against
`app_shared.config.Settings.model_fields` (the class, never an instance — no
environment value is ever in scope). Emits:

- `missing_in_railway` — declared in `Settings`, absent from the service;
- `required_and_missing` — the boot-blocking subset of the above (extra key, see Deviations);
- `unknown_to_settings` — set on the service, unknown to `Settings`;
- `pinned_overrides` — `[{name, railway: "<set>", default: <code default>}]` for
  names that are set AND carry a code default. Required settings are excluded:
  they have no default to pin, so listing them would bury the real pins.
- Defence in depth: a line containing `=` is truncated at the first `=` and the
  remainder is discarded unread; the warning reports a COUNT, never content.
  A test asserts a planted secret appears in neither the JSON nor stdout/stderr.

**`scripts/write_release_manifest.py`** — four additions, all inserted BEFORE
`compute_manifest_id`, so the self-hash covers them (a test asserts tampering
with `toolchain` invalidates `manifest_id`):

- `migrations.alembic_heads` — from `alembic heads` (the command
  `check_single_head.sh` enforces the invariant with). A LIST: two entries is
  itself the finding. `null` when the repo is not an alembic project.
- `buffer_versions` — `netledger_buffer_schema_version` (1),
  `scrape_result_spool_version` (explicit `null` until plan task B1; the import
  starts resolving on its own the moment B1 lands the constant),
  `blocklist_version` (2).
- `toolchain` — `python` (parsed from the `apps/*/Dockerfile` `FROM python:`
  lines; distinct versions are joined so image drift is recorded, not hidden),
  `playwright` (from `uv.lock`), `chromium` (`null` + a `chromium_source` note).
  New flags `--python-version` / `--playwright-version` / `--chromium-version`
  let a build that knows the exact values record them instead.
- `config_names` — the flat sorted setting-NAME vocabulary
  `config_diff_railway.py` diffs against (145 names today).
- Git SHA was already covered: `source.engine_sha` / `source.saas_sha`.

## Deviations
- **`libs/shared/app_shared/netledger/buffer.py` was modified** (out of the
  packet's listed scope for 0.3, which named only the two scripts and the new
  test). The acceptance criterion requires the manifest to carry "the netledger
  buffer schema version constant from `libs/shared/app_shared/netledger/buffer.py`"
  — and no such constant existed (the module has an unversioned `_SCHEMA`
  string). The change is a single additive, non-behavioural module constant
  (`BUFFER_SCHEMA_VERSION = 1`, documenting version 1 as the current
  `netledger_events` shape) plus its `__all__` entry. Nothing reads it except
  the manifest writer, so no runtime path changes.
- **Chromium version is `null`, not a discovered value.** There is no
  `ARG CHROMIUM_VERSION` (nor any other pin) anywhere in the repo: the browser
  image runs `playwright install --with-deps chromium`, so the Chromium build
  is decided by the pinned Playwright version. Inventing a number here would
  defeat the field's purpose (identifying the browser a scrape actually ran
  in), so it records `null` plus `chromium_source` explaining where the real
  value comes from, and `--chromium-version` lets a CI job that ran
  `chromium --version` inside the built image record the true value.
  Equally, "from the image build args" was interpreted as "from the image build
  definition": the Dockerfiles pin Python in the `FROM` line rather than in an
  `ARG`, and Playwright in `uv.lock`, so those are the build args that exist.
- **A third manifest section (`toolchain`) beyond the plan's two.** The plan's
  Files line names `buffer_versions` and `config_names`; putting the
  Python/Chromium/Playwright versions inside `buffer_versions` would have made
  that section's name a lie. Same data, one extra key.
- **`required_and_missing` is an extra output key** not named in the plan's
  interface. It is a projection of `missing_in_railway` (a test asserts the
  subset relation), added because "142 names missing" is useless without "6 of
  them stop the service booting". The three specified keys are unchanged.
- **5 tests were appended to `tests/unit/test_write_release_manifest.py`**
  (a file not listed in scope). The manifest extension would otherwise ship
  untested; the additions are test-only and no existing test was modified.

## Notes for reviewer
- Intended commit message (per packet conventions, NOT committed by me):
  `feat(release): manifest carries buffer versions; config diff by variable name (F20)`
- The new manifest keys change `manifest_id` for every future build. That is
  correct (the id is meant to change when identity facts change) and does not
  affect verification of OLD manifests: `compute_manifest_id` hashes whatever
  keys a manifest happens to have, never a fixed expected set — the existing
  attestation tests still pass unchanged.
- `resolve_alembic_heads` shells out to `sys.executable -m alembic heads` with
  a 60s timeout. `alembic heads` reads `alembic/versions/*.py` via
  `ScriptDirectory` and never opens a DB connection, so it is safe at build
  time with no environment; it costs ~1.2s in the real repo, and the 5 new
  manifest tests add ~8s to the unit suite because each spawns it (it fails
  fast in a tmp repo). If that ever matters, the tests can pass a stub.
- `--allow-dirty` was used for the demo run only (the tree is intentionally
  dirty during an EPA phase). A real deploy still gets the exit-2 refusal;
  that behaviour is untouched.
- `config_diff_railway.py` lets a `PermissionError` from an unreadable names
  file propagate as a traceback rather than exiting 2 (only non-existence is
  handled). Cosmetic; the operator's own export is always readable.
- OWNER GATE (deferred, nothing executed): producing the real names file
  requires `railway variables --service <api|worker|scheduler|scrapers|scrapers-browser> --kv | cut -d= -f1 > names.txt`
  per service, then
  `uv run python scripts/config_diff_railway.py --service <s> --names-file names.txt --out build/config_diff_<s>.json`.
  No Railway command was run and no Railway variable was changed.
