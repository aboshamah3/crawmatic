## Deviations

1. **Time-limit bucket assignment (MINOR).** The plan names exact seconds only for named families (dispatch 600s, reapers/reconcilers 300s, breaker 120s, rollups 1,800s/chunk, discovery 900s/chunk, analysis 900s, webhooks 120s), but the acceptance criterion requires EVERY registered task to carry a limit. I mapped every task not explicitly named to the closest family by its own shape/docstring: `dispatch.generic_price_spider` (tasks_dispatch's thin Scrapyd-dispatch task, registered transitively via `tasks_jobs`, never in `task_names.py`) → dispatch (600s); `MAINTENANCE_PARTITION_CREATE`, `MAINTENANCE_RETENTION_DROP`, `MAINTENANCE_FLEET_BUDGET_ROLLFORWARD`, `COSTAUTH_RESERVATION_SWEEP`, `MAINTENANCE_RECONCILE_PROVIDER_USAGE`, `MAINTENANCE_ENTITLEMENT_REFRESH`, `OUTBOX_DRAIN`, `OUTBOX_RECONCILE`, `STRATEGY_DISCOVERY_SCAN` (new) → reapers/reconcilers (300s); `MAINTENANCE_COST_ROLLUP` → rollups (1,800s, same shape as daily_rollup); `STRATEGY_PATTERN_BACKFILL` → discovery/analysis (900s, it can itself enqueue discovery runs). `soft_time_limit` values (90% of each hard limit) are my own choice — the plan only names hard limits. Impact: none of these choices change public behavior; all are well under the 3,600s ceiling the test enforces, and the unit test (`test_celery_time_limits.py`) pins every value so a future change is deliberate, not silent.
2. **Discovery-scan mechanism design (MINOR, but worth the reviewer's attention).** No bulk/fleet-wide discovery driver existed before this task — `STRATEGY_DISCOVERY_RUN` is only ever enqueued per-key by `resolution.py` (AUTO) or `rediscovery.py` (guarded apply), never in bulk. I designed `STRATEGY_DISCOVERY_SCAN` as a new `maintenance`-queue task (mirroring `STRATEGY_PATTERN_BACKFILL`'s bounded-batch shape) that scans `domain_strategy_profiles` rows stuck at `DISCOVERY_REQUIRED` fleet-wide, in chunks of `STRATEGY_DISCOVERY_MAX_DOMAINS_PER_RUN` (20), persisting progress in the new `strategy_discovery_state` table (mirrors `rollup_watermarks`'/`maintenance_cadences`' global-no-RLS cursor shape) and re-enqueueing itself while a pass is still in progress. This satisfies the literal acceptance criterion ("chunked by domain ... persisted cursor, re-enqueuing until complete") but is new functionality, not a modification of an existing driver — CONTEXT.md's "chunk THERE" pointed at `tasks_strategy.py` as the right file, not at an existing bulk mechanism to modify (there wasn't one).

Deviation impact: MINOR (both are internal implementation choices with test coverage pinning the exact behavior; no public API, billing, or security surface changed).
