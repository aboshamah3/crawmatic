## Deviations
1. **`bytes_compressed` fallback order (MINOR).** The packet says `netledger_middleware.py` writes `bytes_compressed` from `wire_bytes` "for EVERY transport (PROXY and DIRECT)". Implemented as: prefer `meta["wire_bytes"]` when present, fall back to the pre-A7 `bytes_received`-signal total (`_META_RAW_BYTES`) when it is absent (e.g. `process_exception` before any response ever reached the wire-bytes middleware, or the middleware not registered for a given call site/test). This is additive and backward-compatible — every existing offline/integration test that hand-builds a response without `meta["wire_bytes"]` (e.g. `tests/integration/test_network_boundary_recording.py`'s redirect-chain test) continues to get the same number it did before. BROWSER transport is untouched (it already uses `ByteAccumulator.finalize()`'s `main_document_bytes`, a separate, more precise measurement); the packet's parenthetical "(PROXY and DIRECT)" is read as confirming this, not requiring BROWSER to also read `wire_bytes`.
2. **`opsmetrics/emit.py` additions are self-contained functions, not full `OpsSnapshot`/collector wiring (MINOR-to-MATERIAL for B9, flagged below).** The packet's file scope for A7 lists only `netledger_middleware.py`, `opsmetrics/emit.py`, and the scrapers' settings — not `libs/shared/app_shared/opsmetrics/snapshot.py` (where every other metric's live DB collection actually happens, in `collect_snapshot`/`_collect_*`) or `rules.py` (where `Rule(...)` alert entries live). Rather than reach outside the declared scope — snapshot.py is exactly the kind of file a later wave (A5, per CONTEXT.md, is already sharing `emit.py`) could be mid-editing — A7 ships: (a) two pure fraction functions (`ledger_linked_attempt_fraction`, `ledger_bytes_missing_fraction`) that take already-collected counts and return `None` on a zero-signal window (never a fabricated 0%/100%, matching `snapshot._ratio`'s convention); (b) a standalone `render_ledger_coverage_prometheus(LedgerCoverage)` that emits the two named gauges with `# HELP`/`# TYPE`, callable independently of `render_prometheus`; (c) the two `_PROM_HELP` entries; (d) named threshold constants `LEDGER_LINKED_ATTEMPT_FRACTION_MIN`/`LEDGER_BYTES_MISSING_FRACTION_MAX` documented as "for B9 to wire" (not evaluated anywhere — no `Rule` object exists for them yet). **Nothing today calls these with real counts** — the SQL this needs is documented in a code comment directly above `LedgerCoverage` in `emit.py` (COUNT of `request_attempts`/`network_operations` over a 24h window, exact column names). Whoever wires the DB collection (most naturally a new `OpsSnapshot` field + `_collect_ledger_coverage(session, now)` in `snapshot.py`, then one call to `render_ledger_coverage_prometheus` from `render_prometheus`) still has that composition step to do. Flagging this as the one place a reviewer might reasonably want a MATERIAL read instead — see Escalation-adjacent note below.
