## Deviations

1. **The plan's three unit tests are driven by `asyncio.run`, not `@pytest.mark.asyncio`.**
   `pytest-asyncio` is not a dependency of this repo (`pyproject.toml` `[dependency-groups] dev`
   pins `pytest` alone) and is not in `.venv`; an `async def` test without it fails with
   "async def functions are not natively supported", verified empirically. Module-level
   `pytest_pyfunc_call` hooks are not registered by pytest 8 (also verified), so the only
   verbatim-compatible options were adding a dependency (out of packet scope, lockfile change) or
   editing the shared `tests/conftest.py` (out of packet scope, affects ~4k tests). Each test body,
   its assertions and its wire traffic are exactly the plan's; only the driver differs, matching the
   existing convention in `tests/unit/test_browser_ssrf.py`. `unused_tcp_port` is re-implemented as a
   local fixture in the same file.
2. **`resolver` defaults to a new `SystemResolver` (asyncio `getaddrinfo`), not
   `scrape_core.safety.resolver.SafeResolver`.** `SafeResolver` is a Twisted
   `CachingThreadedResolver` returning a `Deferred[str]` — one address, Twisted-shaped — and cannot
   satisfy the plan's own `async def resolve(host, port) -> [(ip, port), ...]` protocol nor the
   "reject if ANY resolved address is private" rule. The safety decision is not duplicated: both
   call `app_shared.url_safety._reject_ip`. `SafeResolver` stays wired as `DNS_RESOLVER` for the
   project's non-Playwright requests.
3. **Proxied legs use an opaque per-process token, not the provider credential, as the context
   proxy password.** The plan's step 4 sketches `password="<context-token>"`; this implements that
   as `EgressGuard.register_upstream(UpstreamProxy(...)) -> token`. The spider still builds the
   sticky username with `sticky_proxy_username` (unchanged, so sticky behaviour and the cost
   ledger's `_is_proxied` view cannot drift) and hands it to the guard; Chromium therefore never
   receives the DataImpulse credential at all.
4. **`tests/unit/test_browser_ssrf.py` was edited**, which is not in the packet's file list.
   `test_subresource_request_passes_without_any_resolver_call` asserted the exact behaviour the
   acceptance criteria require changing ("the subresource branch uses the DNS-aware check"), so it
   could not both stand and the task be done. It is now
   `test_subresource_resolving_privately_is_aborted`, plus
   `test_public_subresource_resolves_once_per_host_not_once_per_asset` for the memo and an autouse
   cache-clear fixture. No other test in that file changed.
5. **`_allow_addresses_for_tests` added** alongside the plan's `_allow_loopback_for_tests`. The
   in-image test needs its fixture pages to load from `127.0.0.1` while a sub-resource resolving to
   `10.0.0.5` is still refused — the all-or-nothing flag cannot express that. The plan's flag is
   unchanged and still used verbatim by the plan's third unit test.
6. **The Dockerfile stage syncs the dev group in and strips it again in the same layer.** The
   existing sync is `--no-dev`, so `pytest` is absent; without this the stage could not run. The
   shipped image still carries no test dependencies.
7. **`--no-sandbox --disable-dev-shm-usage` are appended to the launch args in the image test only.**
   The build stage runs as root with a 64 MB `/dev/shm`, where Chromium's own sandbox refuses to
   start — without them the whole module would SKIP and the build gate would pass vacuously.
   Neither flag affects proxy behaviour. The settings module's own args are asserted, not replaced.
8. **`--host-resolver-rules` is not used** (the plan's step 6 suggests it). Behind a proxy Chromium
   performs no DNS at all, so the guard's own resolver table is the correct — and stricter — seam.

## Notes for reviewer

- **`price_monitor_browser/settings.py` now starts a listener thread at import.** Two unit tests
  (`test_url_safety_hostile.py::test_download_*`, parametrised over both Scrapy projects) exec that
  module, so the unit suite now leaves one daemon thread + one loopback socket alive.
  `ensure_process_guard()` is idempotent, so it is one guard per process however often the module is
  imported. It is deliberately NOT exception-swallowing: a browser node that silently fell back to
  route-hook-only coverage is the state F01 exists to end.
- **The spider uses `get_process_guard()` (never `ensure_process_guard()`).** A unit test that drives
  `_browser_request_for` directly gets `None` and the pre-F01 direct proxy kwargs — correct, because
  in that process Chromium was never launched behind a guard either. The consequence worth knowing:
  the proxy-routing branch is exercised by unit tests only in its `None` (direct-kwargs) form. The
  guard-routing form is covered by the guard's own unit tests plus the in-image test's real launch.
- **Untested path: `_serve_via_upstream`.** Forwarding `CONNECT` to DataImpulse after validation has
  no test — it would need a fake upstream proxy, and no real proxy may be dialed under the no-spend
  assumption. The validation that precedes it is shared with the direct path and is tested; the
  forwarding itself is not. Worth a follow-up test with a loopback fake upstream.
- **The 60 s sub-resource DNS memo is a deliberate, bounded rebinding window.** It is dropped at every
  browser-context switch (the spider compares `meta["playwright_context"]` between dispatches). The
  connection-time guard is unaffected by it — the memo only short-circuits the *route*-layer check.
- **`ssrf.py`'s old docstring claimed this hook was "the only guard that ever sees each
  Chromium-internal navigation — including every redirect hop"**. That claim was false: scrapy-playwright
  attaches `route` per navigation and Chromium follows `Location` internally. The rewrite states the
  correction explicitly, because the false claim is why F01 went unnoticed.
- **Follow-up for A4 (later wave, same Dockerfile):** the new build-gate RUN sits between
  `playwright install` and the `uvx scrapyd-deploy` egg step. A4's uvx pin touches the latter; the two
  edits do not overlap.
- **`app_shared/config.py` may not contain the string `scrape_core` anywhere, comments included**
  (`tests/unit/test_import_boundaries.py`, a raw substring scan). The new settings block says so
  inline, because the next person to document a cross-package setting there will hit it too.
- **`.env.example` not touched** — it documents no other `BROWSER_*` setting either, and all three new
  settings have production-correct defaults.
