## Deviations
1. **Rounding direction on the unit-override example.** The packet's literal acceptance number is "with `PROXY_BILLING_UNIT_BYTES=1000000000` the same bytes price to 1,073,741 micro-USD" (floor of `1_073_741_824 * 1_000_000 / 1_000_000_000 = 1_073_741.824`). `_price_bytes_micro_units`'s existing, explicitly documented contract is to round UP ("Rounding up is the fail-closed direction for a ceiling and costs at most one micro-unit on a settlement") — changing that to floor for one code path would under-book a real proxied byte, which is the exact failure mode H4 (the module's own founding fix) exists to prevent, and would silently change behavior for every other caller of `price_operation_micro_units`/`estimate_reservation_micro_units`, which is a MATERIAL, cross-cutting billing change I am not authorized to make on my own reading of one example number. I kept ceiling division (conservative reading per worker-contract rule 6) and asserted the ceiling-consistent value **1,073,742** micro-USD in `test_a_smaller_billing_unit_prices_the_same_bytes_higher`, with the arithmetic spelled out in the test and its docstring. The default-unit case (`1 GiB -> 1,000,000 micro-USD`) is unaffected by this choice (exact multiple, no rounding). Impact: MINOR — one digit different from the packet's literal example, existing billing behavior (ceiling, fail-closed) is unchanged and documented; flagging in case the plan author intended a deliberate rounding-direction change, which would need an explicit owner decision given its blast radius across every priced operation.
2. **`billing_unit_bytes()`'s `Settings`-failure fallback.** Routing the byte-unit lookup through `get_settings()` means `price_operation_micro_units` (previously a pure function needing no configuration at all) now depends on the ENTIRE `Settings` model validating — `DATABASE_URL`/`JWT_SECRET`/`SCRAPYD_USERNAME`/etc. — which broke the pre-existing `tests/unit/test_cost_estimator.py` (11 tests) in an environment missing those. Added a narrow `except ValidationError` fallback that reads the same `PROXY_BILLING_UNIT_BYTES` env var directly (or the `Settings` field's own default) when full `Settings` cannot be built. Production always has the full required environment (the "fail fast" contract in `test_config.py` is unaffected — this fallback only ever engages when `Settings()` itself would refuse to start, i.e. never in a real deployment), so this is a low-risk, reversible accommodation for isolated unit testing, not a weakening of the production fail-fast posture. Impact: MINOR.
Deviation impact: MINOR
