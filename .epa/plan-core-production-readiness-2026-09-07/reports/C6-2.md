New to this attempt:

1. **`libs/shared/app_shared/jobs/batching.py` edited (outside the packet's file list).**
   Unavoidable: the criterion names `batch.initial_transport`, and `Batch` is defined
   there. C4 already put the *fact* on `ResolvedTarget.transport` (the ladder's resolved
   rung) but `plan_batches` discarded everything except `match_id` when it built a
   `Batch`, so the number could not reach the call site. `plan_batches` now groups the
   targets themselves; its output is otherwise byte-identical (pinned by the unmodified
   `tests/unit/test_jobs_batching.py`, 116 related tests green).
2. **Three `Batch` fields, not one.** `initial_transport` alone cannot tell a first
   attempt from a climb, and the criterion also requires the *coalesced* request count,
   which `len(match_ids)` is not. `cheap_transport` and `unique_physical_requests` are
   the other two inputs the criterion names, carried the same way. All three default to
   `None` and every consumer falls back to the pre-F18 behaviour.
3. **`reservation_rung()` added to `costauth/service.py` (in scope).** The ladder speaks
   `AccessMethod` (`DIRECT_HTTP`, `PLAYWRIGHT_PROXY`, …); the budget speaks
   `DIRECT`/`PROXY`/`BROWSER`. No mapping between the two existed anywhere in the repo.
   One table, in the module that owns reservations, exported so a test can assert the
   mapping is total over `AccessMethod`.
4. **A `RETRY` keeps its purpose even on an escalated rung.** `_batch_authorization_request`
   upgrades the caller's purpose to `PROXY_ESCALATION`/`BROWSER_ESCALATION` when the batch
   is a climb — except for `RETRY`. Rationale is in the docstring: a stall re-POST is a
   second attempt on the rung already authorized, not a new climb, and relabelling it
   would change which C2 degradation rules can deny it. This is the conservative reading
   (it preserves today's behaviour exactly on that path); the alternative is a
   product decision about degraded-mode retries, which is not this task's to make.

## Notes for reviewer

**The missing input turned out NOT to need a DB column.** The dispatch instruction
allowed one Alembic revision if a column was genuinely needed. None is: C4's
`a7c31d0f9e42` already added `domain_playbooks.cheap_path`, `_resolve_domains_and_modes`
already loads the playbook once per pass (`_load_playbook_strategies`), and the ladder's
selected `AccessMethod` was already being attached to `ResolvedTarget.transport`.
Everything C6 needed was in memory and was being thrown away one layer later. Head is
still `a7c31d0f9e42`, single.

**`initial_transport` is the RESOLVED rung, and `cheap_transport` is the playbook's
`cheap_path`.** The criterion's phrase is "`batch.initial_transport` from the playbook's
`cheap_path`", and for a fresh target those are the same thing — C4's ladder orders
candidates with `cheap_path` first. They diverge exactly when the target has already
climbed, and that divergence is what now makes a dispatch an escalation. Reserving the
cheap path for a batch that is about to fetch over a proxy would under-reserve; reserving
the resolved rung and *labelling* it an escalation is single-booked and honest.

**Where escalation is booked, and where it is not.** `escalation_reservation()` is called
from the dispatch site when the resolved rung is paid and differs from the playbook's
cheap path — a separate grant, at the FULL cost of the rung climbed to, never a top-up
mutating the cheap rung's live grant. It is **not** wired into the reactor-side ladder
(`scrape_core.targets.next_strategy_attempt`), which is where a spider climbs mid-run;
that is a spider change and C4's report already flags the same boundary for the fallback
cap. Today a mid-run climb still runs under the grant the dispatch took. Follow-up, not a
regression: pre-C6 that grant was always the paid one, and it still is whenever the
planner does not know the rung.

**Unknown degrades, it never raises.** Three separate "we do not know" paths all land on
the pre-F18 fail-closed mode derivation: no `initial_transport` attached (every pre-C6
caller, every existing test), a chunk whose members disagree, and a transport string this
build has never heard of (logged at WARNING, not raised — a strategy row carrying a new
`AccessMethod` must not crash a dispatch pass). Tests 6 and 7 in the subprocess sweep pin
the last two.

**`unique_physical_requests is None` means "nobody attached an identity", not
"len(match_ids)".** `_unique_physical_requests` returns `None` when no target in the chunk
carries a `canonical_url_hash`, because an absent identity is the absence of evidence, not
evidence that every fetch is distinct. The call site's fallback to `len(match_ids)` is
where the conservative number is chosen, so the two ideas stay separable.
`_unique_physical_requests` calls `coalescing.coalescing_key` — the ONE equivalence key —
via a lazy import (`coalescing` imports `batching` at module scope; a module-level import
back would be a cycle), so this count can never disagree with what `cluster_for_coalescing`
actually folds. Note the count is computed **per chunk**, so a same-URL cluster split
across a chunk ceiling is counted as two fetches — which is what actually happens.

**`PLAYWRIGHT_DIRECT` maps to `BROWSER`, not `DIRECT`.** It makes no proxy request, so its
bytes are free, but it still occupies a browser node for wall-seconds and
browser-seconds are the dimension the `BROWSER` scope bounds. Calling it free because its
bytes are free would be the exact over-optimism F18 is the mirror image of. Pinned by
`test_an_unproxied_browser_still_bills_as_browser_not_direct`.

**Untested path:** the real `CostAuthorizationService.authorize()` reacting to a
`transport="DIRECT"` / `estimated_cost_micro_units=0` request. The call site is unit-tested
against the constructed `AuthorizationRequest`; whether the *service* has a fleet budget
row under `scope_key="direct"` for every workspace, and what it does when it does not, is
DB behaviour and belongs in `tests/integration/test_cost_authorization.py`. Worth a look
before this reaches production traffic: a DIRECT batch that is denied for want of a
`direct` budget row would be a new way for free traffic to stop, which is precisely what
"still authorized for breaker/entitlement/concurrency" must not become.
