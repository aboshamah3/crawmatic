## Implementation notes
- `build_inventory(root, archive)` classifies `generation` by the first path segment relative to `root` (`dr`→dr, `saas`→saas, `pre_variant_*`→pre-variant, else other), opens the archive exactly once (`tarfile.open(..., "r:*")`, iterating members, matching by `<root.name>/<relative-path>`), and computes `sha256_matches_archive` only when `in_archive` (else `null`).
- `keep_reason` precedence: `"newest-not-archived"` for anything not in the archive (regardless of generation) → else `"latest-two-dr-sets"` if the file's `dr` "set" (either the `dr/sets/<set-name>/` directory, or the bare filename for flat `dr/<file>` layouts — both layouts exist: the unit test fixture is flat, production `/srv/crawmatic/backups/dr/sets/` is nested) is one of the two dr sets with the newest max-mtime → else `null` (deletable). This matches production reality: `dr/sets/set-20260906T200001Z/` and `dr/sets/set-20260907T*/` (3 sub-sets on 09-07) are correctly protected even though some are already archive-covered.
- The script never deletes, moves, or renames anything — verified by code review (no `os.remove`/`shutil.rmtree`/`Path.unlink` calls anywhere in the file).
- `--docker` prints du-style per-generation totals plus `docker system df` (via `subprocess.run`, non-fatal on missing binary or failure — degrades to a `SKIPPED`/`FAILED` line, never raises, matching the "ENOSPC/resource failure is not a task failure" assumption).
