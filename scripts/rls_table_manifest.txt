# Format: <table><TAB><class><TAB><annotation>
#
# This file is the human half of the isolation contract.
# `scripts/provision_db_roles.py --verify` reads the DATABASE CATALOG
# (pg_class.relrowsecurity / pg_class.relforcerowsecurity / pg_policy /
# the presence of a workspace_id column) and diffs it against these
# declarations in BOTH directions:
#
#   * a catalog relation missing from this file FAILS the check — an
#     unreviewed table is a table whose isolation nobody looked at;
#   * a declaration that no longer matches the catalog FAILS — so a
#     migration that drops a policy, or adds a workspace_id column to a
#     table declared SYSTEM, cannot pass by leaving this file alone.
#
# The inventory is never derived by walking Python model subclasses. A
# relation can exist in the database with no mapped class — every
# monthly partition, `alembic_version`, `_smoke_foundation`, anything
# created by hand during an incident — and those are precisely the
# relations a subclass walk cannot see.
#
# PARTITION CHILDREN ARE NOT LISTED. They are derived from pg_inherits
# at verify time and inherit their parent's class, so this file needs no
# new line each month and reads identically against databases that have
# materialised different numbers of monthly partitions (production had
# more months than the scratch database this was generated from).
# The derivation is not cosmetic: a partition is an independent relation
# with its own policies, and `SELECT * FROM request_attempts_2026_08`
# is checked against the CHILD's policies, not the parent's.
#
# CLASSES
# -------
#   WORKSPACE    Carries a `workspace_id` column: one workspace owns each
#                row. Must have ENABLE + FORCE ROW LEVEL SECURITY and at
#                least one policy, on the parent and on every partition.
#
#   TRANSITIVE   Holds tenant data but has NO `workspace_id` column of
#                its own. Scoped through a parent row by an `EXISTS`
#                policy. The annotation names the parent table and the
#                join column, because that indirection is the whole
#                reason the table looks unscoped to a column-based
#                audit.
#
#   SYSTEM       No tenant data. RLS deliberately absent. The annotation
#                says WHY the table is tenant-free — that claim is what
#                a security reviewer is actually checking.
#
#   TENANT_ROOT  The workspace registry itself.
#
#   GAP          Holds tenant-LINKED data with NO row-level security.
#                A KNOWN, ANNOTATED hole, not an exclusion. --verify
#                reports every GAP on every run so it cannot go quiet,
#                and flags it if RLS later appears (the annotation would
#                then be stale).
#
# DUAL-SCOPE NOTE: four WORKSPACE tables carry TWO policies rather than
# one (`emit_global_readable_rls_policy`): a `FOR SELECT` policy
# admitting `workspace_id IS NULL` rows as platform-global defaults, and
# a `FOR ALL` write policy that still requires `workspace_id = <ctx>` on
# both USING and WITH CHECK. A global row is readable by every
# workspace BY DESIGN and writable by none of them through the tenant
# path. They are marked "dual-scope" below.

# --- WORKSPACE ---
access_policies	WORKSPACE	dual-scope: proxy/retry policy per workspace; NULL workspace_id rows are platform-default policies, readable by all, writable by none through the tenant path.
api_keys	WORKSPACE	CREDENTIALS (P0.5). Hashed API keys per workspace. Pre-auth lookup by key prefix is the sanctioned BYPASSRLS seam (get_auth_session); every post-auth read is workspace-scoped.
competitor_product_matches	WORKSPACE	Which competitor URL matches which of the workspace's variants — the core competitive-intelligence asset. Parent of two TRANSITIVE sidecars below.
competitors	WORKSPACE	Competitor domains a workspace tracks.
cost_budgets	WORKSPACE	COST (READY-006). The TENANT cost-budget counters, one row per (workspace_id, period_key): a nullable limit plus a reserved_* and a settled_* counter for each of the four dimensions (money in integer minor units, bytes, request count, browser-seconds). This is the AUTHORITATIVE store — not Redis: every C3 authorization takes SELECT ... FOR UPDATE on this row, which is what makes the hard ceiling a database property instead of a race the application hopes it wins. Written on the tenant seam by app_shared.costauth.service; also written cross-tenant by the lease sweeper on the sanctioned BYPASSRLS system seam (crawmatic_auth / get_system_session), which is inherently fleet-wide and must additionally read network_operations. Added at head f1a7c02de5b4.
cost_reservations	WORKSPACE	COST (READY-006). One row per C3 authorization grant: the four reserved dimensions, the lease (lease_expires_at), and a state that moves exactly once, RESERVED -> SETTLED | RELEASED, by compare-and-set. Tenant-owned because a grant is a claim on ONE workspace's budget — deliberately unlike C1's network_operations, which is fleet-owned because a physical fetch can serve two workspaces. Written on the tenant seam by app_shared.costauth.service (authorize/heartbeat/settle/release) and cross-tenant by the lease sweeper on the sanctioned BYPASSRLS system seam. A partial unique index over (workspace_id, dedupe_key) WHERE state = 'RESERVED' collapses redelivered requests onto the live grant they already have. Added at head f1a7c02de5b4.
control_plane_rules	WORKSPACE	CONTROL PLANE (C1). The SaaS's declared monitor/reprice intent per tenant — kind/cadence/target_external_ids addressed by the SaaS's own external_id, UNIQUE within the workspace (never globally: two tenants may each name a rule "rule-1"). Links to the engine refresh_rules row that actually drives the scrape via a nullable refresh_rule_id, ON DELETE SET NULL — retiring the engine rule must null the pointer, never delete the record of what the customer asked for. RLS in the SAME migration that creates the table. Deliberately NOT registered in WORKSPACE_OWNED_MODELS in the schema change itself (the NetworkOperationAllocation precedent: that belongs with the control-plane read/write routes). Added at head c8d2e3f4a5b6.
dispatch_intents	WORKSPACE	JOBS (P0.5). Planned dispatch units per scrape job; added at head e7b21f3a8c94.

domain_strategy_methods	WORKSPACE	Versioned extraction methods per strategy profile; carries its own workspace_id (not transitive) so the column-based check covers it directly.
domain_strategy_profiles	WORKSPACE	Per-domain scraping strategy state, incl. discovery cooldowns.
match_current_prices	WORKSPACE	Latest observed competitor price per match — the read-hot pricing surface.
network_cost_rollups	WORKSPACE	COST (C6). Durable, bounded-cardinality per-tenant daily cost buckets — one row per (workspace_id, rollup_date, domain, http_method, profile_version), capped at TOP_N_COST_ROLLUP_BUCKETS+1 per (workspace, day) via a top-N + "other" collapse. Populated by app_shared.netledger.rollups.run_cost_rollup from network_operations/network_operation_allocations on a durable rollup_watermarks cursor (key "network_cost_rollup"), never computed synchronously on request. RLS in the SAME migration that creates the table. Read by the new tenant-scoped GET /v1/cost-rollups (scope-gated, never on the ops-shared surface) — registered in WORKSPACE_OWNED_MODELS because that read path ships in this same change, unlike its sibling network_operation_allocations above. Added at head ccea48aab7b1.
network_operation_allocations	WORKSPACE	COST (P0.7). The tenant-visible half of the C1 physical network ledger: one row per (physical operation, workspace) carrying that workspace's exact scaled-integer fraction and its allocated cost in currency minor units. This is the ONLY RLS'd table of the three — its two fleet-owned siblings below have no workspace_id to scope by. A deferred constraint trigger re-checks at COMMIT that one operation's allocations sum exactly to the operation cost; it aggregates ACROSS workspaces and runs as the invoker, so an allocation SET must be written on the sanctioned BYPASSRLS system seam (crawmatic_auth / get_system_session) like the scheduler's due-rule claim. A tenant connection attempting a cross-tenant cost split sees only its own row and fails the check closed, which is the intended outcome. Added at head c4b19e7a2f08.

# --- TRANSITIVE ---
match_audit_classifications	TRANSITIVE	No workspace_id of its own. Scoped through competitor_product_matches via match_id: policy is EXISTS(SELECT 1 FROM competitor_product_matches p WHERE p.id = match_id AND p.workspace_id = <ctx>). Deleting the parent match removes the only path to these rows.
match_competitor_identifiers	TRANSITIVE	No workspace_id of its own. Scoped through competitor_product_matches via match_id, same EXISTS predicate as above. Added at head a3f5c81d7e46.
refresh_tokens	TRANSITIVE	CREDENTIALS (P0.5). No workspace_id of its own. Scoped through users via user_id: policy is EXISTS(SELECT 1 FROM users p WHERE p.id = user_id AND p.workspace_id = <ctx>). Added at head b6d94c2f1a70 (EPA B8b), closing the GAP the B8 audit recorded here. A SUPER_ADMIN's users row has workspace_id IS NULL, so its tokens match no context at all — fail-closed, deliberately. The platform never reads this table through the tenant path: issue, rotate and revoke are all keyed by an unforgeable token_hash before any principal (and therefore any app.workspace_id) exists, so all three run on the sanctioned BYPASSRLS auth seam (get_auth_session), exactly like the pre-auth user-by-email lookup. The policy confines crawmatic_app, which otherwise reads every user's refresh-token hashes across every workspace via its blanket SELECT grant.
strategy_attempt_stats	TRANSITIVE	No workspace_id of its own. Scoped through domain_strategy_profiles via domain_strategy_profile_id: EXISTS(SELECT 1 FROM domain_strategy_profiles p WHERE p.id = domain_strategy_profile_id AND p.workspace_id = <ctx>).

# --- SYSTEM ---
_smoke_foundation	SYSTEM	Non-domain fixture table created by migration 023a24e5717d to prove the migration/mixin foundation works. Its `group_key` is a synthetic grouping key, NOT a workspace id, and nothing writes tenant data to it. Carries no FK to workspaces.
alembic_version	SYSTEM	Migration bookkeeping: one row, one column (version_num). Read by GET /version. Both runtime roles hold SELECT only; INSERT/UPDATE/DELETE are revoked so only crawmatic_migrate advances it.
api_abuse_limit_counters	SYSTEM	EPA W5.5-L1 item 2. Fail-closed, Postgres-authoritative counter store behind app.abuse_limit's AbuseLimitMiddleware, guarding the abuse-able surfaces (discovery trigger, manual recheck, usage export, /v1/admin). Deliberately NOT row-level-secured: its only columns are a salted-free sha256 bucket key (`abuse:<surface>:<sha256(credential)[:32]>`, never a raw credential), a window timestamp and a counter — nothing identifies a workspace, and the limiter must be able to count an attempt made by a caller whose workspace is not yet resolved (the middleware runs BEFORE the auth seam, which is the entire point: an unknown credential must not be a free request). A policy keyed on app.workspace_id would make every counter write fail closed under FORCE RLS and 429 the API. UNIQUE PK on (bucket_key, window_starts_at) is load-bearing (see the migration docstring) — the limiter's increment is a single INSERT ... ON CONFLICT DO UPDATE ... RETURNING serialised on exactly this index. Rows expire by becoming unreachable as the window moves on, not by deletion; a sweep (DELETE ... WHERE window_starts_at < now() - interval '2 days') is owed to tasks_maintenance.py by a future task, per the migration's RETENTION note. Added at head e92029e9902c.
domain_lifecycle_audit	SYSTEM	EPA W4.1. Append-only transition log for domain_playbooks.state (from_state/to_state/evidence/approver/profile_version per row) — one row per app_shared.domains.lifecycle.transition call. UPDATE and DELETE are both rejected by a trigger (same append-only pattern as network_operation_settlements), so "append-only" is a database property, not a convention. Fleet-scoped like its parent: no workspace_id, FK'd to domain_playbooks.domain (the existing unique index), and carries the same non-tenant reasoning domain_playbooks' own entry states — a domain's certification HISTORY is exactly as non-tenant as its current state. Seeded ACTIVE rows (amazon.sa/noon.com/stech.ink, migration d9a46612bcc8) predate this trail: their first transition() call produces this table's first row for that domain, not a gap. Added at head 9f24d748ba13.
domain_playbooks	SYSTEM	Platform-wide scraping playbooks keyed by public domain (preferred access method, profile/policy names, method templates). Seeded by scripts/seed_domain_playbooks.sql, identical for every tenant, contains no customer data — knowing that amazon.ae is scraped with a given method reveals nothing about any workspace.
domain_rules	SYSTEM	EPA B5 (F10). Fleet-wide per-domain host admission ceiling (fleet_concurrency / fleet_rate_per_minute, both NULL = use the FLEET_HOST_*_DEFAULT setting) read by app_shared.limiter.fleet.resolve_fleet_limits and enforced by admit_fleet's Redis lease at the physical request boundary. SYSTEM for exactly the reason domain_playbooks and fleet_cost_budgets are: the row names a public domain and a fleet-wide number, carries no workspace_id and no tenant-identifying column, and knowing that amazon.sa is capped at N concurrent fleet requests reveals nothing about any workspace. Deliberately NOT the tenant domain_access_rules table (WORKSPACE, above): that one is per-workspace and tenant-writable, this one is the shared ceiling every tenant is admitted against and no tenant may read or set. Every non-key column is nullable with no server default so a later column (EPA C1's request_timeout_seconds) is a catalog-only ADD COLUMN, no rewrite. Added at head e7b34c0af219.
fleet_cost_budgets	SYSTEM	COST (READY-006). The FLEET provider cost budget, keyed by scope_key (a provider/period scope, not a workspace) — the same counter block as cost_budgets above. Deliberately global with NO workspace_id and no RLS, exactly like proxy_circuit_breakers: the money is spent against one shared operator provider account, so one tenant's runaway loop spends everyone's budget and the ceiling must be readable AND decrementable from every workspace's scrape path. A tenant-scoped policy here would hide the fleet ceiling from precisely the connections it exists to stop. SYSTEM rather than GAP because the row names a provider and a month and carries no tenant-identifying column — contrast C1's network_operations, whose domain/canonical_url_hash/scrape_job_id are tenant-LINKED and which is therefore filed GAP. Added at head f1a7c02de5b4.
fleet_network_cost_rollups	SYSTEM	COST (C6). Durable, bounded-cardinality FLEET-wide daily cost buckets — one row per (rollup_date, domain, http_method, profile_version, currency), summed across every tenant, capped at TOP_N_COST_ROLLUP_BUCKETS+1 per day via the same top-N + "other" collapse as network_cost_rollups above. SYSTEM rather than GAP (contrast network_operations/provider_usage_records, both GAP because a raw row's domain is tenant-linked): a fleet SUM across every workspace is not tenant-linked evidence — it reveals aggregate fleet spend on a domain, not any one tenant's usage of it, the same non-tenant reasoning fleet_cost_budgets/domain_playbooks use for their own SYSTEM filing. Read by GET /ops/metrics's cost_rollup section (fleet aggregate health only — tenant breakdowns are NEVER served from this table or from that surface; see network_cost_rollups above). Added at head ccea48aab7b1.
maintenance_cadences	SYSTEM	Scheduler bookkeeping: one row per maintenance task key with its next_due_at/last_run_at. Fleet-wide by construction (the maintenance sweep runs once for the whole deployment, not once per tenant) and holds no tenant-identifying column.
proxy_circuit_breakers	SYSTEM	Fleet-wide proxy kill switch keyed by scope_key (a provider/domain scope, not a workspace). Deliberately global: a breaker that tripped for one tenant must stop the burn for all of them.
refresh_rule_occurrences	SYSTEM	EPA B3 (F07). The scheduler's due-time identity ledger: one row per (rule_id, scheduled_for) occurrence `fire_refresh_rule` actually fired, INSERTed before the job is created so the primary key — not a lock — is what decides whether a second scheduler replica may fire the same occurrence. Fleet-wide by construction (the due-rule claim spans every tenant and runs on the BYPASSRLS system session) and holds no tenant-identifying column — the same shape and rationale as maintenance_cadences/rollup_watermarks/strategy_discovery_state. `rule_id` is NOT a foreign key: the log audits what the scheduler DID, so deleting a rule must not delete the evidence of its firings. Added at head d3f7a1b62c85.
rollup_completion	SYSTEM	EPA C7 (F12). Per-day daily-rollup checkpoint: one row per UTC day with the keyset cursor of the last committed batch and a `complete` flag. Fleet-wide by construction (one rollup day spans every tenant) and holds no tenant-identifying column — the same shape and rationale as maintenance_cadences/rollup_watermarks. `last_key_workspace_id` is a scan POSITION, not a tenant reference, and is not a foreign key. Read by app_shared.maintenance.rollups (resume) and by the C8 retention gate (`complete` decides whether a day's price_observations partition may be dropped). Added at head b3f0c95a7d21.
rollup_watermarks	SYSTEM	Rollup cursor bookkeeping: one row per rollup key with the highest UTC day fully aggregated. Fleet-wide by construction (one daily rollup window spans every tenant) and holds no tenant-identifying column — the same shape and rationale as maintenance_cadences. Added at head 05dfda7cdbb7.
strategy_discovery_state	SYSTEM	EPA B4 (F09). Cursor bookkeeping for the fleet-wide, chunked STRATEGY_DISCOVERY_SCAN sweep over domain_strategy_profiles rows stuck at DISCOVERY_REQUIRED — one row (key="global") recording the last profile id forwarded in an in-progress pass. Fleet-wide by construction (one scan pass spans every tenant's profiles) and holds no tenant-identifying column — the same shape and rationale as maintenance_cadences/rollup_watermarks. Added at head 096ff6d343b5.

# --- TENANT_ROOT ---
workspaces	TENANT_ROOT	The tenant registry itself. Deliberately carries no RLS: it is the root every policy's `app.workspace_id` refers to, admin provisioning creates a workspace BEFORE any context could apply to it, and the row holds only a name/slug/status. Confidentiality of the LIST of workspaces is a control-plane concern (the admin router's service token), not a row-level one.

# --- GAP ---
# `refresh_tokens`, the one entry this section held before, was closed by
# EPA B8b at alembic head b6d94c2f1a70 and now sits under TRANSITIVE
# above. The two entries below are NOT that kind of gap: they are a
# deliberate design decision recorded here rather than a hole nobody has
# gotten to. They are filed as GAP anyway — not SYSTEM — because SYSTEM
# means "no tenant data", and a row naming a scrape_job_id, a domain and
# a canonical URL hash is tenant-LINKED even though no single tenant owns
# it. Filing them SYSTEM would make --verify go quiet about a real
# read-side exposure; filing them GAP makes it say so on every run, which

network_operations	GAP	COST (P0.7). The PHYSICAL network operation — one row per thing that happened on the wire. FLEET-owned BY DESIGN: it deliberately carries no workspace_id, because one browser navigation can serve two workspaces watching the same competitor URL and a subresource fetch belongs to no logical attempt at all; tenant ownership is a derived allocation, and lives in network_operation_allocations above. Not transitively scoped either: scrape_job_id is nullable by design (a fleet-side probe has no job), so an EXISTS-via-parent policy would hide exactly the fleet rows the ledger exists to record. The residual exposure is READ-side: crawmatic_app's blanket SELECT grant lets a tenant connection read every workspace's operation domains, canonical URL hashes and scrape_job_ids. Closing it means REVOKing tenant SELECT on this table once C3/C4 have established which reads actually need it — a grant change, not a policy, and deliberately out of C1's schema-only scope. Added at head c4b19e7a2f08.
network_operation_settlements	GAP	COST (P0.7). Append-only provider reconciliation facts over network_operations (written by C5): a correction appends a higher settlement_version and UPDATE/DELETE are rejected by trigger, so the current reconciled cost is the latest version. Fleet-owned for the same reason as its parent above — a settlement restates the PHYSICAL cost, and re-deriving each tenant's share of a corrected total is an allocation concern. Carries no tenant identifier of its own beyond the operation_id it points at, so its exposure is strictly the parent's, with the same crawmatic_app SELECT-grant remedy. Added at head c4b19e7a2f08.
provider_usage_records	GAP	COST (P0.7/C5). Raw provider usage evidence — one immutable row per line of an imported provider export (app_shared.netledger.reconcile.import_provider_usage / scripts/import_dataimpulse_usage.py), append-only via trigger (UPDATE/DELETE rejected, identical pattern to network_operation_settlements). FLEET-owned like network_operations: no workspace_id at all, because a provider bills a provider ACCOUNT, not a workspace. Filed GAP rather than SYSTEM for the SAME reason network_operations is GAP and not SYSTEM (contrast fleet_cost_budgets/domain_playbooks, which carry no tenant-identifying column whatsoever): target_host is a domain-shaped column, and a domain is tenant-linked evidence — it reveals what is being scraped and how heavily — even though no single row-level tenant owns it. The residual exposure is the identical READ-side one network_operations already carries (crawmatic_app's blanket SELECT grant), plus this table's sub_user/pool_identifier columns, which the DataImpulse export runbook flags as credential-ADJACENT (identifiers, never a password/token) — worth folding into the same future SELECT-grant remedy noted on network_operations, not a reason to weaken the classification here. Added at head 7c2b9e5a41d6.
network_operation_resource_summaries	GAP	COST (C9, F14). The COMPRESSED form of a browser navigation's subresource children: one row per parent network_operations row carrying child_count, a bytes_by_host_class JSONB map over a CLOSED three-value host class set, bytes_total and duration_ms_sum, written by app_shared.maintenance.ledger_summaries immediately before those children are deleted in the same transaction. FLEET-owned exactly like the network_operations parent it describes: no workspace_id, no RLS policy, and parent_operation_id carries no foreign key (network_operations is partitioned since a5e0c74b13d9, so its only UNIQUE constraint now includes created_at; and a summary must outlive a parent whose partition is eventually dropped at 730 days). Filed GAP rather than SYSTEM for the SAME reason network_operations and provider_usage_records are: it carries no tenant column, but it names an operation whose domain and canonical URL hash are tenant-LINKED evidence, so the residual read-side exposure from crawmatic_app's blanket SELECT grant is the parent's, inherited. Closing it is the same future grant change already noted on network_operations. Added at head d1f7a3c9e284.
network_operations_pre_partition	GAP	COST (C9, F14). TRANSIENT. The pre-swap copy of network_operations, left in place by a5e0c74b13d9 rather than dropped: it is the only rollback from the partition swap that does not require re-copying the whole ledger, and disk is the cheaper of the two risks. It holds exactly the rows network_operations held at swap time and is written by nothing — the swap drops its append-only trigger precisely so it stays inert. Every application role has ZERO privileges on it (see grants_expected.yaml): nothing should read a frozen shadow of the ledger, and a copy readable by crawmatic_app would widen the very read-side exposure the network_operations entry above already flags. Filed GAP, not SYSTEM, because its rows are the parent's rows and carry the parent's tenant-LINKED domain/canonical_url_hash columns. **OWNER ACTION: after verifying the swap, DROP TABLE network_operations_pre_partition and remove this entry, this table's grants_expected.yaml entries and its provision_db_roles.sql entries.** Until then --verify names it on every run, which is the point. Added at head a5e0c74b13d9.
extraction_shadow_events	SYSTEM	EPA C5 (F19). One row per MATERIAL disagreement between the first-hit extraction chain and the W3.2 ranker, recorded while EXTRACTION_RANKING_POLICY is 'shadow' so the C11 owner decision on flipping it to 'v1' rests on a counted rate rather than an argument. Written by scrape_core.pipelines._flush_batch draining the in-process buffer scrape_core.extraction.pipeline fills, inside the SAME transaction as the observations it shadows. Fleet-scoped: no workspace_id, no RLS — it is evidence about an extraction POLICY on a DOMAIN, and the decision it feeds is one flag for the whole fleet; any single workspace_id here would be an arbitrary pick among the workspaces watching that page. crawmatic_app gets the same DELETE/INSERT/SELECT (no UPDATE) every other fleet table gets — INSERT because the persistence flush runs on the app DSN until A10's scraper DSN cutover; crawmatic_scraper gets INSERT only, alongside its price_observations/request_attempts ingestion grants. Append-only by convention, not by trigger. Added at head c1e7b93a40df.
